---
title: Updating the API and code reference
---

The checked-in `packages/docs/open-api.json` describes registered HTTP routes.
Export it from a local application built from the revision being documented,
using the intended authentication mode. Browser Google consent/session transport
and owner-delegated machine account controls have different authentication.
Never copy the upstream hosted application's schema into this fork.

## Export the runtime contract

From the repository root, with the combined local application running:

```bash
curl --fail --silent --show-error http://localhost:3000/documentation/json \
  | jq "." > packages/docs/open-api.json
```

Use your own loopback port when verifying an isolated instance. This endpoint
returns schemas, not workspace records. Review the output before committing;
never include real credentials or request evidence as examples.

For the machine-only contract, use authenticated `GET /api/admin/openapi.json`.
`GET /api/admin/operations` lists the required grants. That live contract is
authoritative for MCP discovery; the checked-in reference does not grant access.

## Generate endpoint pages

Use the repository's pinned generator rather than downloading a new release:

```bash
yarn workspace docs exec mintlify-scrape openapi-file open-api.json \
  --outDir api-reference/auto
```

Update the API Reference navigation in `packages/docs/docs.json` with the
generated page paths. Keep handwritten examples, cover every registered
operation, and remove generated pages for retired routes. Public ingestion,
signed callbacks, human account/session APIs and workspace machine APIs have
different authentication boundaries; documenting a route does not make it a
bearer-key or MCP operation.

Every product/control feature must include its authenticated typed MCP operation
in the same change. Run `yarn check:mcp-parity` before marking the feature complete;
the isolated route/catalog gate does not touch application databases. Add an
actual MCP consumer scenario for changed behavior, not only documentation.

## Refresh the function inventory

```bash
node packages/docs/scripts/generate-code-inventory.cjs
node packages/docs/scripts/generate-code-inventory.cjs --check
```

The inventory records package functions, methods, signatures, source locations,
parameters, declared return types and existing JSDoc. It is a source map, not an
arbitrary-function execution API. See [coverage](/guide/api-coverage).

Run the documentation preview from `packages/docs` with `mintlify dev`.
